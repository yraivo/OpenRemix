# Remix 1.7.1 跨版本迁移、安全审计与独立构建技术文档

> 前篇：[Remix 1.6.3 混淆样本逆向分析与源码恢复技术文档](Remix-1.6.3-Recovery-WP.zh-CN.md)。
> 本文档记录 **Remix `1.7.1`** 源码恢复的两个完整阶段：**第一阶段**复用 `1.6.3` 方法论完成外层剥离、跨版本迁移、Java 层与隐藏载荷入口审计及运行时缺陷修复；**第二阶段**彻底移除 36,209 份保护层生成文件、完成全树分包命名与结构正常化，最终收敛为本仓库主分支的 **标准 Java 8 Gradle / `javac` 独立构建工程**。

## 2. 第一阶段：跨版本迁移、外层剥离与入口审计

### 2.1 基于结构指纹的跨版本对齐
跨版本迁移不可依赖短混淆名或文本相似度直接替换。首先对 `1.6.3`（3,453 个核心类）与 `1.7.1`（3,584 个核心类）依据继承图、成员签名与指令指纹建立精确坐标映射：
- 共建立 **1,909** 对类坐标、**17,666** 对方法坐标、**8,290** 对字段坐标；
- 其中 **10,127** 个方法在绑定坐标后字节码严格等价（10,060 个连同声明一致），分布于 1,849 个类，但仅有 **302** 对类的全部方法完全相同。

该分布表明，跨版本最可靠的复用单位是恢复规则、源码表示与校验工具，而非整类机械搬运。

### 2.2 外层剥离与隐藏载荷管理
- **外层剥离**：纯静态移除外层 loader/attach/native 共 **95** 个条目（涉及 77 个 root class / 81 个 owner），将 Manifest 入口直接恢复为游戏 `Main`，并经常量池引用边核查确认保留主体无残余直接引用。
- **隐藏载荷**：沿用 `archive_location + internal_owner + name + descriptor` 唯一身份索引管理 12,068 份 masked-gzip 载荷；最终两个 loader 约束为仅读取包内固定资源，限定压缩输入上限 8 MiB、展开上限 16 MiB，并校验精确长度与 `CAFEBABE` 魔数，异常即终止。

### 2.3 迁移返工：方法体一致但构造器字段初始化缺失
旧版反编译器常将构造器中的字段赋值提升至字段声明处。若迁移时仅复用旧构造器方法体、却沿用新版不含初始值的字段声明，将产生**编译零错误但运行时对象状态缺失的类**：

```java
// 旧恢复源码将赋值提升至字段声明，构造器方法体本身不含赋值语句
private float speed = 0.5F;
Client() { initialize(); }

// 仅迁移构造器 body 而遗漏声明 initializer，会导致字段写入静默缺失：
private float speed;
Client() { initialize(); }
```

针对该根因，按方法描述符展开同类 `this()` 委托闭包，系统核查了 **4,190** 个匹配构造器：最终在 19 个类中恢复了 **103 个不同字段**的初始化逻辑（114 个 constructor/field 对），另有 10 个默认值等价字段记录省略。

### 2.4 编译通过后的运行时缺陷修复
在全源编译零错误的基础上，通过受控测试环境、本地回环 TCP 夹具及实际运行定位并修复了以下典型缺陷：

1. **归纳变量宽度与初始化顺序**：`MathHelper` 及另外 3 处循环计数器被反编译为 `byte`，遍历大表时发生符号溢出；同步修复 `BlockPos` 静态初始化顺序及集合构造重载歧义。
2. **地形渲染授权门禁**：世界已加载 289 个区块，但 `visible render infos = 0`。排查发现渲染缓存读取区块状态前存在“本地授权字符串非空且长度为 4”的隐蔽门禁，移除该条件后地形 mesh 恢复正常绘制。
3. **动物构造路径线程炸弹**：运行时发生原生线程 `OutOfMemoryError`（线程编号增至 `Thread-157xxx`）。溯源发现动物实体构造器在授权状态失败分支会启动递归派生新线程的破坏类；定点移除该分支并中和其 `run()` 方法。
4. **Netty 4.1 direct `ByteBuf.array()` 漏迁**：初期迁移遗漏了 `1.6.3` 已验证的规则，切换至锁定 43 库（含 Netty `4.1.140.Final`）后在 TCP status 解码触发 `UnsupportedOperationException`。统一替换为有界 `byte[]` 读取 helper（保留长度与字符集校验，且不分配中间 `ByteBuf`）。
5. **菜单、ClickGUI、光影与联机门控**：
   - 移除展开主菜单图标点击及多人直连构造器上残留的旧反射启动标志门控；
   - 补齐本地启动路径的按键事件订阅器，修复 HUD UID 空指针，移除无授权标志时强制向 `lightmap` 写入随机色彩的分支（保留正常界面开关）；
   - 修复资源包目录不存在时 `delete()` 短路 `mkdirs()` 的逻辑，迁入 `1.6.3` 的未绑定键码 `0` 过滤，并将每帧 OpenGL 错误轮询改为 `-Dremix.debugGlErrors=true` 显式开关。
6. **自定义材质包 CTM 纹理错配**：启用 OptiFine 连接纹理（CTM）时草地与石英均错误匹配至首条黑玻璃规则。根因系 `TextureAtlasSprite` 的 `String` 构造器迁移遗漏两个索引字段的 `-1` 初值，导致全部 2,227 个贴图索引均落入 `0`；补回初值后恢复正常。
7. **多人服务器位置同步异常（移动包 `Y+2` 门控）**：定位到移动与转头数据包中残留的旧反射计数门控——绕过原加密启动后，上报与位置回执的 `Y` 坐标均被加高 `2`。移除该门控后，10 组边界坐标序列化及真实 TCP 位置回执均恢复准确。

### 2.5 应用层与隐藏载荷入口审计
对全部 **39,827** 个应用定义（27,759 普通定义 + 12,068 隐藏载荷）及 **296,773** 条调用边进行检索与逐域人工复核，并将运行依赖锁定为 **43 份库**（其中升级了 Log4j `2.26.1`、Netty `4.1.140.Final`、Guava、Gson、Commons、HttpClient 等）：

- **确认并处置的风险项**：
  1. **服务端聊天 `ClickEvent` 至本地命令注入边界**：AutoHypixel 自动重玩路径收紧为仅允许 `RUN_COMMAND` 且严格匹配 `/play [A-Za-z0-9_]{1,64}`，入队与发送前双重校验当前命令前缀；
  2. **本地日志暴露 Session Token**：将启动日志中的 legacy session ID 替换为固定文本 `Session initialized.`；
  3. **授权失败目录重定向**：移除授权失败时将配置目录切换至 `user.home` 下随机子目录的逻辑；
  4. **无界线程与超时控制**：`VanishDetector` 限制为 2 守护线程、32 容量队列、UUID 去重及 5 秒连接/读取超时；本地扫描命令入口补充参数合法性校验；
  5. **冗余高危能力与推广逻辑**：移除未使用的 `Unsafe` / `System.exit` 反射注册、读取配置自动打开推广网页、应用内残留 `System.loadLibrary` 与通用脚本桥（精确拦截规则扩充至 37 条）；同时完整继承 `1.6.3` 的破坏回调、进程枚举、TLS 校验、遥测及全局代理认证清理。
- **甄别并保留的正常路径（误报排除）**：
  - `ServerAddress` 中的 JNDI 仅使用固定 `dns:` 与 `_minecraft._tcp.` 执行游戏服务器 SRV 解析，不构成外部可控的 LDAP/RMI 注入；
  - 局部 `ObjectInputStream` 仅对本地刚序列化并加密的字节流执行自回读；
  - 事件总线所需的 `IMPL_LOOKUP` 与固定包内反射未发现外部输入可控链路。
- **审计边界说明**：上述审查覆盖应用 Java 类与隐藏载荷；第三方原生库（LWJGL / JInput 以及公开依赖中 JNA 内含的原生二进制）主要核对来源与差分，未做逐指令逆向审计。此外，当前源码保留原版客户端在运行期将用户输入的账号与代理密码明文写入 `Accounts.txt`、`Proxies.txt` 的行为。

## 3. 第二阶段：消除保护层、语义重命名与独立构建重构

第一阶段完成后，客户端已具备安全构建与运行能力，但 40,064 份哈希源码及复杂的编译后 ABI 处理链仍不利于长期维护与代码阅读。第二阶段围绕“去保护层、可读化、脱离后处理”实施了系统性重构。

### 3.1 批量消除 `o/` `g/` 保护层（40,064 → 3,855 文件）
依据恢复清单与 `javac` 符号判定，将 589 处通用调用包装展开为常规 Java API 调用、5 处剩余字面量调用展开为字符串常量，彻底剔除 `o/`、`g/`、12,068 份载荷模板、gzip 加载器与投影类——**一次性移除 36,209 份生成文件**，源码规模由 **40,064** 份缩减至 **3,855** 份。

### 3.2 包布局归整、控制流结构化与语义命名
在单模块 `Aura` 可读性试验明确机械清理与人工语义确认的边界后，按批次对整树实施整理：
- **包归属迁移**：通过 `javac` 符号分析重排 **1,008** 个类（323 个归回 `net.minecraft.*`、8 个归回 `optifine`、10 个归回 `shadersmod`，334 个已禁用的旧认证/编解码框架类归入 `remix.compat.legacy.*`，清空根 `xyz` 与根目录散落类型）；
- **消除哈希文件名与控制流噪声**：全树 `Class_*`、`EnumBuild_*` 文件名归零；将块内向前跳转标签结构化改写为 `if/else`；批量移除仅透传同一异常的私有冗余方法；基于 `javac` 类型归属恢复 **1,470** 处哈希局部变量命名（覆盖 456 个文件）。

### 3.3 枚举、分发表、内部类与构造器正常化（3,583 → 3,321 文件）
为彻底摆脱历史 ABI 兼容层依赖，依次完成三轮结构正常化：
1. **枚举与分发表（3,583 → 3,405）**：恢复全部 **226** 个枚举的直接常量声明，将 **14** 个常量专属子类合回枚举体内，移除 **128** 个分发表支撑类，将 **173** 处枚举 `switch` 转换为具名常量分支。
2. **内部类与支撑代码（3,405 → 3,322）**：基于单创建点且无外部类型引用的严格条件，将 **79** 个独立辅助类（谓词、比较器、回调、监听器）合回 60 个所属类的静态内部类；底层工具归入 `remix.compat.compiler`、`remix.compat.library` 与 `remix.security`；记分板 38 处标准名称改为直接常量声明。
3. **构造器正常化（3,322 → 3,321）**：逐项处置全部 **113** 组 `ConstructorPrefix` 构造器（59 组合并为常规构造器、54 组转为不带占位参数的普通状态捕获私有重载），移除 `ConstructorPrefix.java`（全树净减 968 行）。

### 3.4 稳定性维护
- **Scaffold / HUD / MotionBlur**：修复无碰撞箱方块命中空指针及 Y 边界误用 Z 的逻辑缺陷；`Speedometer` 增加玩家与世界空上下文防护；`MotionBlur` 支持资源刷新后重注册，并在现有 `ShaderGroup` 上实时更新 `Phosphor` uniform。
- **生命周期与配置容错**：`LocalPlayer` / `FullBright` / `Xray` / `Spectator` 在切换世界或上下文失效时显式释放状态；JSON 配置逐项校验字段类型并拒绝 `NaN`/`Infinity`，单条损坏记录隔离报错而不中断后续有效配置加载。
- **亮度所有权与真实药水保留**：`FullBright` 与 `Xray` 共享 `WorldBrightnessOverride` 亮度覆盖所有权，最后一个使用者关闭时恢复原始亮度表；`FullBright` 夜视模式改为纯渲染层效果，不再向实体注入无限夜视或清除真实药水效果。

### 3.5 退出全部后处理：迁移为标准 Gradle / `javac` 构建
最后移除阻碍普通源码直出的 3 处遗留挂钩：
1. 核实 `GuiLanguageList`、`GuiStatsStatsMobsList`、`GuiStatsStatsItem` 的父类构造器不依赖子类未初始化字段，移除最后 3 处 `ConstructorOrder` 标记与空标记类；
2. 源码级移除 `TwitchStream` 的 5 处旧原生库加载调用，使 `MinecraftClient.initStream` 直接采用 `NullStream`；
3. 移除 `CommandHandler.registerCommand` 残留的旧打包授权门禁，恢复单人世界 `/time set 1000` 等内置服务端命令注册。

至此，旧二进制名称还原、226 个枚举布局重写、54 个构造器折叠、lambda 与访问标志后处理**全部退出构建链**。最终交付成为标准的普通 Java 8 工程：
- **构建输入**：`3,321` 份 `.java` 源码 + `src/main/resources` + `43` 份锁定依赖（`libs/`）；
- **构建输出**：标准 `.\gradlew.bat clean build` 或 `.\Build-Plain.ps1` 直接产出 `Remix-1.7.1.jar`（`3,538` 个 class，约 12.5 MB），运行时直接使用源码类名与行号；
- **回归验收**：使用 Gradle 直出 JAR 通过本地协议 `47` 测试服连接（注册 94 个模块）、事件派发、Speed/TargetStrafe、语言/统计/ClickGUI/创造栏绘制、配置容错、FullBright/Xray/MotionBlur 切换，以及单人超平坦世界创建、聊天执行 `/time set 1000` 与存档退出回归。

## 4. 当前源码盘点与已知边界

截至公开发布的 `OpenRemix` 主分支源码树：
- **实测已清零项**：`0` 份保护层生成类、`0` 个 `Class_<hash>.java`、`0` 个 1~2 字符混淆类名、`0` 处 `field_<hash>`；公开导出时删除了 Vineflower 反编译器注释（2,393 行独立注释与 4 处行尾注释，其中部分涉及控制流与同步结构提示），且经 JDK 8 `javac` 与 Gradle 双路验证零错误编译通过。
- **核心模块目录**：`remix/module/`（162 个文件）中仅 4 个文件命中 6 处 `method_<hash>`。
- **仍保留的尾项**：
  - 全树 989 个文件中尚存 **1,391** 个 `method_<hash>` 声明（`remix/` 占 451 个，多为旧混淆器遗留的静态哨兵 getter 与已禁用旧认证辅助方法）；
  - `net/`、`optifine/`、`shadersmod/` 下保留常规 MCP SRG 名称（`func_*` / `field_*`，`remix/` 内为 0）；
  - `remix.compat.compiler`（`JvmBooleanSlots`、`JvmThrowTypes`）作为普通 Java 实现保留，以维持与原 JVM 语义一致。
- **验收边界**：上述回归覆盖核心单人、渲染、配置与本地协议路径，不代表全部 94 个模块的任意组合、外部在线正版认证或全部第三方材质/光影包均已逐一验证。
